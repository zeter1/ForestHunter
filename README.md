# 🐗 Forest Hunter — Ultimate Hunt

[![Validate](https://github.com/zeter1/ForestHunter/actions/workflows/validate.yml/badge.svg)](https://github.com/zeter1/ForestHunter/actions/workflows/validate.yml)

**Forest Hunter — Ultimate Hunt** — браузерный 3D FPS на **Three.js/WebGL**, в котором игрок охотится на кабанов, собирает оружие и припасы, выполняет контракты, прокачивает персонажа и сражается с боссом **Альфа-вепрём**.

Текущая версия игры: **2026.07.27-improved**.

## Возможности

- Большая лесная 3D-локация.
- Несколько типов кабанов:
  - обычный;
  - быстрый;
  - бронированный;
  - бешеный.
- Босс **Альфа-вепрь**.
- AI с состояниями патрулирования, преследования, рывка и атаки.
- Ограничение одновременно атакующих противников, чтобы бой оставался читаемым.
- Система уровней и опыта.
- 18 улучшений в трёх уровнях редкости.
- Контракты с наградами.
- Серии убийств и бонусы за комбо.
- Попадания в голову и критические выстрелы.
- Лут с противников.
- Аптечки, боеприпасы и оружие на карте.
- Взрывающиеся красные бочки.
- Капканы и мины.
- Радар как одно из улучшений.
- Броня, регенерация, вампиризм, берсерк и другие перки.
- Настраиваемая сложность, качество графики, чувствительность мыши и громкость.
- Полноэкранный режим.
- Web Audio API для звуков.
- HUD с HP, бронёй, боеприпасами, уровнем, XP, контрактом и серией убийств.
- Индикатор направления полученного урона.
- Экран выбора улучшений после повышения уровня.
- Кинематографическая камера смерти.
- Рекорд результата между сессиями браузера.

## Сложность

Доступны три режима:

- **Лёгкая**
- **Нормальная**
- **Тяжёлая**

Сложность влияет на здоровье, урон и скорость противников, частоту появления врагов, число одновременно атакующих кабанов и множитель очков.

## Контракты

Во время охоты выдаются задания, например:

- уничтожить заданное количество кабанов;
- выполнить серию попаданий в голову;
- уничтожить особых противников;
- добиться определённой серии убийств.

За выполнение выдаются очки, опыт, здоровье и боеприпасы.

## Запуск

Основной entrypoint — `index.html`, а JavaScript runtime разделён по `src/`.

Можно открыть проект напрямую в современном браузере, однако для более предсказуемой работы рекомендуется локальный HTTP-сервер:

```bash
python -m http.server 8000
```

Затем открыть:

```text
http://localhost:8000
```

## Требования

- современный настольный браузер;
- WebGL;
- JavaScript;
- клавиатура и мышь;
- подключение к интернету для первоначальной загрузки Three.js.

Используется **Three.js r128**. Основной CDN — cdnjs, предусмотрена резервная загрузка через jsDelivr.

## Графика

В игре доступны три режима:

- низкое качество;
- среднее качество;
- высокое качество.

Для производительности используются:

- `InstancedMesh` для деревьев, кустов, камней и части растительности;
- пулы частиц, трассеров, вспышек и гильз;
- пространственная сетка для коллизий с деревьями;
- ограничения количества врагов и объектов;
- упрощение AI на большой дистанции;
- кеширование моделей оружия;
- адаптация количества визуальных эффектов.

## Архитектура

Deep Gameplay Decomposition разделяет runtime по subsystem contracts:

```text
index.html
├── src/core/
│   ├── storage.js
│   └── seeded-rng.js
├── src/game/
│   ├── config.js
│   ├── progression.js
│   ├── environment.js
│   └── runtime.js
├── src/ai/
│   ├── config.js
│   └── boar-brain.js
├── src/weapons/
│   ├── config.js
│   ├── geometry.js
│   └── combat-rules.js
├── src/audio/audio-system.js
├── src/ui/
│   ├── dom-cache.js
│   └── hud-model.js
├── tests/
│   ├── contracts.mjs
│   ├── scenarios.mjs
│   └── fixtures/forest-replay.json
├── scripts/validate-structure.mjs
└── docs/ARCHITECTURE.md
```

Environment ownership и чистая AI/combat/progression/HUD-математика вынесены из runtime. В 2.2 `stepBoarState`, seeded damage rolls, reload/deployable timelines и hit ordering стали replayable simulation contracts; `src/game/runtime.js` остаётся Three.js entity/input/effects orchestration boundary. Подробнее: **[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)**.

## Диагностика

Если игра не запускается:

1. Откройте DevTools браузера через `F12`.
2. Проверьте вкладку **Console**.
3. Убедитесь, что WebGL доступен.
4. Проверьте доступ к cdnjs / jsDelivr.
5. Попробуйте запуск через локальный HTTP-сервер вместо `file://`.
6. При низкой производительности переключите качество графики на **Низкое**.

Если Three.js не загрузился с обоих CDN, игра показывает отдельное сообщение об ошибке.

## Ограничения

- Игра ориентирована на ПК с клавиатурой и мышью.
- Three.js загружается с внешнего CDN.
- Three.js entity lifecycle, movement execution, raycasts/effects и input остаются в `src/game/runtime.js`; AI transitions и combat timelines уже проходят через dependency-injected simulation contracts.
- Полного browser end-to-end набора пока нет; интерактивный gameplay требует отдельной runtime-проверки.
- CI проверяет HTML/JavaScript и статическую раздачу, но не заменяет реальную WebGL/gameplay-проверку на GPU.

## Проверка и CI

Workflow [`.github/workflows/validate.yml`](.github/workflows/validate.yml) запускается на изменениях `index.html`, `src/**`, `scripts/**` и workflow. Он проверяет:

- синтаксис всех JavaScript-файлов;
- module structure и порядок bootstrap;
- gameplay contract tests для AI, combat/reload/deployables, collision, progression и HUD;
- deterministic replay scenarios для boar state machine, damage rolls, reload, hit ordering и deployables;
- отсутствие возврата вынесенной simulation logic в runtime;
- headless Chrome/WebGL boot до маркера `data-forest-boot="ready"`;
- diff hygiene через `git diff --check`.

CI **не доказывает** полный gameplay runtime: pointer lock, Web Audio, GPU performance, баланс и поведение AI требуют отдельного interactive/manual уровня.

### Рекомендуемый runtime smoke test

1. Открыть стартовое меню.
2. Изменить сложность и графику.
3. Начать охоту.
4. Проверить движение, бег и прыжок.
5. Проверить стрельбу и прицел.
6. Подобрать новое оружие.
7. Проверить переключение оружия и перезарядку.
8. Установить капкан и мину.
9. Получить новый уровень и выбрать улучшение.
10. Выполнить контракт.
11. Проверить появление босса.
12. Проверить смерть, итоговый экран и сохранение рекорда.
